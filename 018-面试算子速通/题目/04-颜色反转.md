# 颜色反转（Element-wise）

**LeetGPU：** Easy · Color Inversion  
**目录：** `element_wise/02_color_inversion`

图像是一维 `unsigned char` 数组，按像素打包 **RGBA**（每通道 8 bit）。原地反转颜色，**A 不动**：

$$
R'=255-R,\quad G'=255-G,\quad B'=255-B,\quad A'=A
$$

`image` 长度 `width × height × 4`。前 4 个数是左上角像素。

## 接口

```cuda
void solve(unsigned char* image, int width, int height);
```

- `image` 是 **device** 指针，**原地**写回
- 不得改签名

## 为什么归 element-wise

每个像素只读自己的 RGBA、只写自己。没有邻域、没有归约。和 vector add 同一模板：grid-stride + 向量化。差别只是：

- 类型是 `unsigned char`，不是 `float`
- 4 个通道绑在一起，A 要跳过
- 原地，没有单独 `out`

## 做法

1. **naive：** 线程 `i` 对应像素 `i`，下标 `4*i .. 4*i+2` 做 `255-x`。
2. **uchar4：** `cudaMalloc` 16 字节对齐，像素数个 `uchar4`。一次读写 4 通道，改 `.x.y.z`，`.w` 原样写回。合并访存、指令更少。
3. 计算强度 ≈ 3 次整数减 / 8 字节读写，**带宽墙**。再优化结构没用。

## 和 vector add 对照

| | vector add | color invert |
|---|---|---|
| 并行 | 一个输出一个点 | 一个像素一个点 |
| 向量化 | `float4` | `uchar4` |
| 原地 | 否 | 是 |
| 墙 | HBM | HBM |

## 小例子

输入 1×1：`[10, 20, 30, 255]` → `[245, 235, 225, 255]`
