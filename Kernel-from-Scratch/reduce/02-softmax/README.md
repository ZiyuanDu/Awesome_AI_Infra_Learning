# Softmax

**LeetGPU：** Medium · [Softmax](https://leetgpu.com/challenges/softmax)

对一条连续 FP32 向量做数值稳定的 Softmax：

$$
m=\max_i x_i,\qquad s=\sum_i e^{x_i-m},\qquad y_i=e^{x_i-m}/s.
$$

接口保持：

```cuda
void solve(const float* input, float* output, int N);
```

输入、输出都是调用方分配的 GPU 数组，长度均为 N，互不重叠；输入有限，1≤N≤500000。例：`[1,2,3] → ≈[0.090,0.245,0.665]`。

## 面试讲解顺序

[solve.cu](solve.cu) 不足 100 行，[bench.py](bench.py) 保持约 50 行。块内归约复用 [reduce.cuh](../reduce.cuh)。

1. **稳定计算**：先减最大值，再计算指数与分母。
2. **缓存与访存**：线程把输入保存在寄存器中，float4 读写；未对齐地址和最后不足四个元素时使用标量路径。
3. **线程内归约**：四条独立的 max/sum 累加链减少依赖，再调用共享的 warp/block 归约。
4. **只用一个切换点**：N≤16384 时，一个 block 完成全部计算；线程数按 N 从 32 倍增至最多 512。更长的向量每块处理 4096 个值，使用 128 个线程。
5. **合并分块统计**：第一阶段写各块的 `(m_b,s_b)`，第二阶段合并并输出：

$$
m=\max_b m_b,\qquad s=\sum_b s_b e^{m_b-m},\qquad y_i=e^{x_i-m}/s.
$$

这是沿归约维拆分的 split reduction。Softmax 合并时需要重标定指数和，不能直接相加各块已经归一化的概率。每个输出 block 读取一份很小的统计表，省掉第三次 kernel 启动。当前范围最多 123 组统计量；扩大输入上界时，需要重新设计统计表容量与读取方式。

分派只依赖长度，最多几次 CPU 整数判断，没有运行时搜索或设备参数查询。两次 kernel 在同一 stream 中顺序执行，提供跨 block 的阶段边界。

### 哪些辅助细节需要理解

第二阶段每线程读取一组统计量，题目上界下有 `ceil(500000/4096)=123≤128`，因此一块线程足够读取全部统计量。面试口头说明这个推导即可，代码省略 `static_assert`；这项约束仍然成立，并不是删除断言后就能处理任意大的 N。

`CUDART_INF_F` 是 CUDA 定义的正无穷 float 常量，前面加负号就是负无穷。无效位置补 `-∞`，既不影响最大值，也在取指数后贡献零；这里不能补零，因为零会给指数和增加不存在的元素。

`load4/store4` 是向量访存的优化辅助函数。一次处理四个连续 float，需要四个元素都有效、实际地址满足 16 字节对齐；代码用 `alignof(float4)` 表达这个要求，见 [CUDA 向量类型对齐表](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html#built-in-types)。例如 `N=6,i=4` 时，读取结果是 `{x[4],x[5],-∞,-∞}`，写回时只写 `y[4]`、`y[5]`。

面试先讲清 max、exp、sum、归一化和跨块合并；讨论访存优化时再解释 float4。若明确约定输入输出地址已对齐，可以省略地址检查，但任意 N 的尾部仍要处理。`__device__` 表示函数在 GPU 执行，`__forceinline__` 用于强制内联小函数；内联标记不改变数学语义。

### 整体取舍

| 内容 | 面试版处理 | 原因 |
|---|---|---|
| `static_assert` | 省略 | 参数关系可以口头推导，不影响当前计算 |
| `N<=0` 分支 | 省略 | 题目已保证 N≥1 |
| 额外 stream 入口 | 省略 | 只保留三参数、默认 stream 的 `solve` |
| 减最大值与负无穷填充 | 保留 | 数值稳定性和无效元素的正确处理 |
| 对齐检查、标量尾部 | 保留 | 当前支持未对齐地址与任意有效长度 |
| 分块 `(max,sum)` 的重标定合并 | 保留 | 整条长向量正确归一化的关键 |
| 寄存器缓存、float4、四路累加 | 保留 | 已测试的性能优化，讲解时放在数学主线之后 |
| 内联与展开标记 | 保留 | 减少辅助调用和固定循环开销，不必作为面试讲解重点 |
| 一次分配的临时统计缓存 | 保留 | 保持完整三参数接口，避免每次调用重复分配 |

## Workspace 是什么

它只是每块两个 float 的临时统计数组，当前上界为 `123×8=984` 字节。

唯一的三参数 `solve` 入口用于单 GPU、默认 stream：先决定线程和 block 数，再启动统计及必要的归一化 kernel。小输入不分配临时内存，大输入按 host thread 首次分配并复用，在线程退出时释放。

`Scratch` 只负责这块小缓存的生命周期；`thread_local` 指 CPU 线程，不是每个 GPU 线程都分配一份。面试若约定 workspace 已经准备好，可以省略这段资源管理，直接使用给定的临时数组；可运行文件保留它来避免重复分配。

实现中没有内存池配置函数、CUDA Graph、实时调参或手写 CUDA 错误检查框架。完整正确性检查在测试侧完成。

## 运行与正确性

```bash
python reduce/02-softmax/bench.py
```

需要 NVIDIA GPU、CUDA Toolkit、PyTorch 和 Ninja。编译、正确性检查及首次 workspace 分配不计入性能计时。

精简脚本覆盖 45 个长度、输入与输出各四种地址偏移，共 **720 次检查**，对照 FP64 Softmax，并检查输出前后的保护区。

同布局计算内核的临时完整测试另覆盖 **61 个长度、110 组输入、1002 次方案校验、28 次共享归约检查**，包括 32/256/4096/16384 等边界及相邻长度、常数、大数平移、宽动态范围和末尾峰值。CUDA 实现最大绝对误差 `5.96e-8`，概率≥1e-7 部分最大相对误差 `1.24e-6`，概率和最大误差 `2.38e-7`。`sm_89` 编译确认两个 kernel 无 stack/spill。精简入口另用当前 720 次检查复核。

## 与其他方案比较

完整研究对照包括 CUDA 单 warp、单 block、分块 online、cuDNN 9.20 的 ACCURATE/channel 路径，以及两种手写 Triton 3.7.1 对照。Triton 融合方案采用标准的 load/max/exp/sum/store 结构，分块方案用两个 kernel、4096 个元素一块；思路可参考 [Triton fused softmax 教程](https://triton-lang.org/main/getting-started/tutorials/02-fused-softmax.html)。这些对照未进行全面 autotune，不代表各框架的性能上限。

为区分计算与 Python 开销，研究脚本另用 Graph 重放摊薄调用开销。以下仅是该口径下的 GPU 侧数据，最终精简脚本使用上面的普通调用计时：

|---:|---:|---:|---:|
| 32 | 1.55 | 0.92 | 0.90 |
| 4096 | 1.74 | 1.61 | 1.63 |
| 4097 | 1.84 | 2.64 | 3.23 |

| 65536 | 4.15 | — | 3.04 |
| 499999 | 5.38 | — | 8.00 |
| 500000 | 5.37 | — | 4.80 |

本实现与所测 Triton 对照在 4K–16K 的部分长度接近或更快；500000 时 GPU 侧约慢 12%，65536 时约慢 37%，极小输入仍有差距。非整除长度也可能反过来占优，因此需要测试尾部，不能只看单个规模。

同一完整研究脚本的普通调用中，本实现在 61 个长度均快于所测 Triton 分块对照；这包含 C++ 与 Python 启动开销差异，不能解释成 CUDA kernel 全面更快。当前版本的定位是代码长度、稳定性与并行度之间的面试取舍，保留一个分界，不为每个长度增加专用实现。
